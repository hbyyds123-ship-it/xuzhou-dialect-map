请人录方言，难的从来不是"录音"这一步 —— 是交接。
老人用手机念了二十条，发过来一堆新录音 1、新录音 2， 谁也不知道哪条对哪个词，这堆声音就废了。
语言包就是为了解决这件事：一张能打印的念稿单 + 一个能对号的清单， 你把它给出去，收回来导进这一卷，词条上就有了真人声音。

混着走的后果：格式不一样，导不进去；就算硬塞进去，"这话是谁说的"也丢了 —— 而这句话正是整套东西的价值所在。

02怎么让人录四步，对方不需要装任何软件
  1. 先开一个包（下面第 03 节） 选好词、填上发音人，得到两样东西：一份清单 .json、一张念稿单。
  2. 把念稿单打印出来（或截图发过去） 纸上每一行是一个词：编号、词、拼音、意思，最后留一格空着写"你家怎么说"。
  3. 让对方照着念，一条录一段 手机自带录音机就行。iOS 是「语音备忘录」，安卓多半叫「录音机」。不用联网、不用注册。
  4. 把音频发回来，导进这一页 按 01、02 命名最省事；不改名也认 —— 会按录音顺序对号，并在导入报告里一条条列出来给你核对。
规矩 1一条一段，按 01、02 的顺序。连成一整段的录音要在中间切，切错了就对不上词。
规矩 2开头先说一句："我是王秀兰，沛县张寨人，1950 年生。" 这句话本身就是这条录音的身份证。
规矩 3不认识就跳过，别硬念。跳过的词空着，比编一条假的有用得多 —— 这一卷的价值在"真"。
规矩 4安静、离嘴一拳。关掉电视和风扇，手机别捂着，别在院子里录（风噪救不回来）。

别用微信的语音消息发 —— 那种条形的语音存成文件， 音质被压过、也对不上号。要发就发「文件」（微信里选「文件」而不是「语音」）， 或者干脆用数据线拷、用网盘传。录音机里存下来的 .m4a / .mp3 / .wav 都认。

对方会自己开电脑、有麦克风？那最省事：把这一卷的录音页给他 —— 录音页，录完直接导出演示包发你，一条都不会错位。

06格式要自己写脚本生成、或要核对清单时看这里
{
  "format": "xiangyince-pack/1",
  "packId": "pk...",
  "createdAt": "2026-11-07T12:00:00.000Z",
  "volume":  { "no": 1, "name": "徐州", "dialect": "徐州话" },
  "speaker": { "name": "王秀兰", "birthYear": 1950,
               "hometown": "沛县张寨", "years": 60, "note": "" },
  "license": "发音人同意……",
  "items": [
    { "no": 1, "wordId": "yibengzi", "word": "一崩子",
      "py": "yī bēng zi", "meaning": "一段时间",
      "file": "01.m4a", "data": null, "note": "" }
  ]
}

音频有两种给法：file 写文件名，音频文件单独给； 或者 data 填 base64，整包就是一个 .json（方便微信发）。
对号优先级：file 精确同名 → 文件名里的编号（1–3 位，不认长串时间戳）→ 文件名就是词/词条 id → 录音顺序。
只写 wordId 是必须的：word、py、meaning 只是给人看的， 程序靠 wordId 认词。单条上限 24MB，一包上限 500 条。
