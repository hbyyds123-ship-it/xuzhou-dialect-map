# 方言采样台 · 记录此时此刻的语言

一个出题器 + 一个录音机 + 一个私有存档。系统出题，你照着说，声调当场算成数字与曲线，最后导出成一个**给孩子的、能脱离本程序打开**的文件。

全程本地：不联网、不上传、不调用任何语音识别服务。

---

## 一、怎么跑

本目录已与《管！徐州》方言地图合并在同一个仓库里，服务器在**仓库根**（同源是两边的前提）：

```bash
cd ..                    # 到仓库根 xuzhou-dialect-map/
node serve.cjs           # 或 node serve.cjs 8080
```

- 采样（能录音）：**http://127.0.0.1:8000/recorder/**
- 学习（地图、挑战、图鉴）：**http://127.0.0.1:8000/**
- 直接双击 `recorder/index.html` 也能打开：题目照常出、存档照常读，但**录不了音**——
  页面顶部的「运行环境」徽标会变红并给出上面的地址，录音按钮禁用，不会让你白录。

> 为什么 `file://` 不行：Chrome 把 `file://` 也算「安全上下文」（`isSecureContext === true`），
> 但**不会在这个来源下授予麦克风**。所以判据不能看 `isSecureContext`，要看协议与主机——
> 本目录的自检按 `http: + 127.0.0.1/localhost`（或 `https:`）判定，这是实测出来的口径。

## 一·二、浏览器支持到哪一步

| 浏览器 | 状态 | 凭什么这么说 |
|---|---|---|
| Chrome / Edge（Chromium 156 实测） | **已自动化验证** | `node tools/cross-browser.cjs`：e2e 22 项 + 浏览器检查 6 项，两个内核各跑一遍全绿 |
| Firefox | 未自动化（本机未安装） | 代码按能力探测降级，没跑过就不敢说支持：Firefox 的 CDP 在 129 之后被移除，要另接 geckodriver |
| Safari | 未自动化（仅 macOS） | 已按它的两个老坑做降级：`webkitAudioContext` / `webkitOfflineAudioContext` 前缀、`MediaRecorder` 拒绝未知选项时逐级回退、`decodeAudioData` 回调式 |
| 任何没有 `OfflineAudioContext` 的内核 | 降级可用 | 导出会把这格标成「音频转换失败，请用 JSON 备份」，表格与「说法」仍在（A21d 用运行时复现过） |

三条硬边界（不是"兼容性承诺"，是代码里真做了的）：

1. **录音格式不写死**：`webm;codecs=opus → webm → ogg;codecs=opus → mp4` 逐个问 `isTypeSupported`，
   `MediaRecorder` 构造失败再退回无选项；`blob.type` 取 `mr.mimeType` 而不是写 `audio/webm`（Safari 录出来是 `audio/mp4`，标错会让回放与解码一起挂）。
2. **解码双支**：`decodeAudioData` 先按 Promise 用，拿不到 Promise 就换回调式，并且给回调式另传一份 `ArrayBuffer` 拷贝（这个 API 会 detach 入参）。
3. **地图侧绝不主动建库**：没有 `indexedDB.databases()` 的浏览器直接放弃真人录音优先链，
   绝不为了"试试看"用 `open(name)` 建出一个空库——那会让采样台之后建不出表（`A20` 钉的就是这个事故）。


> **为什么不再提"行号契约"**：旧做法是外部脚本按固定行号（134–200 / 203–216 / 504–528）切片求值。
> 它有两个问题：任何一次插入都会让它切到错的代码且不报错；实现方为了对齐行号会做无意义的排版。
> 本轮合并给 `app.js` 加了 25 行索引回写，`encodeWavBase64` 就从 504 移到了 505，旧守卫随即变红。
> 现在 `tools/extract.cjs` 按缩进标记定位，`node tools/anchor-check.cjs` 应当常绿；
> 引擎本身另有稳定入口 `window.__probe`，浏览器侧验收直接调函数，不再碰源码文本。

## 一·五、与地图之间的契约（两边唯一的连接点）

| 方向 | 内容 | 落在哪 |
|---|---|---|
| 地图 → 采样台 | 词表：`data/atlas.js` 的 `ATLAS.words`（54 条，字段 `id/w/py/meaning/example/…`） | `prompts-atlas.js` 运行时派生成题目，**不复制数据**；词表加一个词，题库就多一道题 |
| 采样台 → 地图 | 录音索引：`localStorage` 键 **`xzdt.sample.v1`** | 每次保存/删除/清空后由 `syncSampleIndex()` 重写，形状 `{version, updatedAt, count, words:{<atlasId>:{clipId, clips[], saying, speaker, gen, newest}}}`，实测 1 条约 200 B |
| 采样台 → 地图 | 音频本体：**IndexedDB** 库 `xz-dialect-rec` / store `clips` | 地图只读不写；`features/sample.js` 按索引里的 `clipId` 取出 blob 播 |

四条硬规矩：

1. **音频不进 localStorage**——二进制存不下（5 MB 上限 + base64 膨胀），所以只回写索引。2. **`atlasId` 是唯一连接键**，取 `ATLAS.words[].id`（如 `guan`、`bai`）。词形与 `prompts.js` 原有题相同的
   （实测 3 条：茅子 / 屋当门 / 手捏子），不重复出题，而是把 `atlasId` 挂回原条目，你原来录的那条地图也认得。
3. **地图的「听发音」是一条优先链**：有你的录音 → 播真人说法；没有 → 回落原来的普通话合成音，
   并明说一句「现在播的是普通话合成音，不是徐州话」。它不会假装合成音是方言。
4. **库版本只升不降，只读的一方绝不建库**（这条是被两次事故教出来的）：
   - `open(name, 1)` 对不存在的库就是**创建**它。地图若带版本号去开，会留下一个没有 `clips` 表的空库，
     采样台随后再 `open(name, 1)` 不触发升级，表永远建不出来，录音完全存不进去
     （实测：`put` / `all` 均 `NotFoundError`）。
   - 反过来，采样台若只用「版本 +1」自愈，下一次加载再请求旧版本号会直接 `VersionError`——
     把一次性卡死变成**每次刷新都坏**（实测踩过：`The requested version (1) is less than the existing version (2)`）。
   - 现行规则：地图侧先 `indexedDB.databases()` 确认库存在，再**不带版本**打开；
     采样台侧首次按期望版本开，撞 `VersionError` 就改成不带版本重开，仍缺表才在当前版本上 +1，重试有上限。
   - 回归由 `tools/e2e-check.cjs` 的 **A20**（造 v1 空库 → 存 → 刷新 → 还能存）钉住；
     把降级重试摘掉后 A20c 立刻变红、其余 17 条保持绿——已在工作区外的副本上实测过这条鉴别力。

## 二、这个作业到底在做什么（可直接写进报告）

### 命题

> 不是「记录方言」，而是**采样代际之间的词汇空缺，并标注新词被方言同化的程度**。

「记录方言」是无限大的任务，「记录一个家庭在一个时点上不会说和刚学会说什么」是有限且可完成的。作业的价值来自后者。

### 三个概念

**1. 词汇空缺（lexical gap）与填补策略**
爷爷奶奶的语言里没有「肯德基」，因为这个东西不存在。当它进入生活，年轻人必须补一个说法，而补的过程只有三种策略：

- **直接借音**：就说「肯德基」
- **意译造词**：走「洋柿子／洋火／洋碱」那条老路
- **旧词延伸**：拿一个现成的词硬套新对象

**同一个东西，三种策略，就是三代人的语言距离。** 这是可以逐条记录、最后统计的。

**2. 共时快照，而不是历史考证**
本系统记录的是「此时此刻这个人怎么念」，不是「这个词的调类归属」。所以爷爷说「洋碱」就是对的，哪怕字典写「肥皂」。**规范在这里不适用，事实才适用。**

**3. 二维坐标（这个框架是提出这个想法的人自己的）**
每个新造的说法都可以标在两个维度上：

| | 维度 | 取值 |
|---|---|---|
| X | 流传范围 | 只我家 → 本村 → 本县/镇 → 到处都说 |
| Y | 地道程度 | 不像方言（照搬普通话）→ 半土半普 → 地道 |

把它形式化之后，就从「感觉现在年轻人说话不像方言」变成一张可看的散点图。**这是整个作业里最值钱的一步：把文化感慨变成可测量的量。**

### 一个分布观察（不是统计检验）

> 把每条说法放在「地道程度 × 流传范围」这张 2×4 的表上，看点落在哪儿。

导出的 HTML 里自带这张散点图。**但它只能算描述，不能算检验**，原因有三个，都写在图下面：

- 坐标只有 3×4 ＝ 12 格，格子里的点可能只有一两个；
- 样本约 3 个说话人，同一个人的多条记录**不是独立观测**（他今天说的话和昨天说的话高度相关）；
- 一家人的语料不构成抽样，无法外推到别人家。

所以正文只写「在本样本中观察到点向两个角落聚集」，**不写「负相关成立」**。要检验「越地道的说法越走不出去」，得改采样设计：多个家庭、给出区间，而不是把一家人当成 12 个独立观测。

### 与「语保工程」的区别（答辩必备）

| | 语保工程 | 本系统 |
|---|---|---|
| 单位 | 发音人 | 三代人 × 一个词 |
| 目的 | 科学描写音系 | 留存与教学 |
| 方法 | 固定字表、专业记音 | 出题录音、自动取调、本人标注 |
| 谁来做 | 受过训练的调查员 | 任何一个家庭 |

它采的是**语言**，你留的是**一个人的声音**。这两件事不冲突，也不可互相替代。

## 三、技术实现要点

**1. Local-first，零服务器**
录音与标注存在 IndexedDB（`localStorage` 存不下二进制）。没有任何网络请求，断网可用，不存在「上传」这个动作。

**2. 免 ASR 的结构化采集：题目即标注**
系统不需要听懂你说了什么——题目是固定的，答案就是题目。这样绕开了两个死结：方言没有可用的语音识别；而任何云端识别都违反「不流出」。
**这是整个设计的技术支点。**

**2b. 必填的「说法」字段**
每条记录都要填「**你家的说法**」（用汉字写下来），这是必填项，空着不让保存。

原因很直接：这个作业的核心命题是「新词被方言同化的策略（借音 / 意译 / 旧词延伸）」。**没有汉字写法，就没法统计策略**——音频里听不出「洋柿子」和「洋碱」是同一个词。也正因为如此，导出物里每行都能直接看到说法，散点图的每个点也用说法做标签。

策略归类还带一个「**谁判的**」字段（记录者 / 长辈本人 / 未知）。**记录者自己判的策略不能当证据**，所以判定人要记下来。

**3. 基频（F0）提取 → 整段音高走向**
- 自相关法逐帧求 F0（只在 70–400 Hz 找峰，归一化相关系数 < 0.32 判为清音）
- **倍频纠错**：周期不是整数样本时（如 180 Hz 在 12 kHz 下周期 66.7 样本），相关峰会落在 2T/3T 上，读数直接低八度。做法是取到全局最大相关峰后，**回退到第一个满足 `r ≥ 0.98 × bestR` 的 lag**。实测 170/180/340 Hz 全部回到真值（偏差 ≤ 1%），而 70–150 Hz 的最大扰动只有 +0.8%
- **静音门限**：帧 RMS 的 95% 分位 × 0.15，再配一个绝对下限 1e-3（约 −60 dBFS）。只用相对分位时，整段无声也会被整体放行，界面会画出一条由底噪编出来的曲线
- **类别而不是数字**：把浊音段按三等分比较中位音高，判成 平/升/降/降升/升降；跨度不足 1.5 半音时判「平」，**不出三位数**——长得像调型的数字一定会被人当调型引用
- **外部交叉校验**：与 Praat（parselmouth）独立跑一遍，两条曲线最大偏差 **1.01%**（`node tools/cross-check.py` 需另装 parselmouth）

**这一节把「录音」变成了「可测量的数据」**：同一个词，爷爷和你各录一条，曲线可以直接叠比。

**4. 关闭 AGC 与降噪**
`getUserMedia` 显式设置 `autoGainControl:false, noiseSuppression:false, echoCancellation:false`。
自动增益会把弱音拉强，直接扭曲音高包络——做 F0 分析时开着 AGC，测出来的调型是假的。**这是个容易忽略但决定成败的细节。**

**5. 导出自包含文件（跨十年可播）**
- `OfflineAudioContext` 重采样到 16 kHz 单声道
- 手写 44 字节 WAV 头（RIFF/fmt/data），16-bit PCM
- base64 内嵌进一个 HTML

为什么不用默认的 `webm/opus`：它更小，但旧设备与部分浏览器放不了。存档的寿命比体积重要。16 kHz 单声道对语音足够，且**任何平台都能播**。

## 四、一次采样的建议流程（约 40 分钟）

1. 先录**桶2 新事物**（10 题）：最快，也最容易有意外收获
2. 再录**桶1 老器物**（16 题）：可以先打电话问长辈，再录自己的版本
3. 然后**桶3 家词**（8 题）：这一桶只能你自己填，别人替不了
4. 最后**句子**（8 题）：录语序和语气，前面的词条录不到这些

标注时**别都选「地道」**。诚实标注才有分析价值——你要的是分布，不是好看。

## 五、这套东西的局限（写进报告会加分）

1. **音高读数是「整段级」的，不是音节级。** 题库里**一条单音节题都没有**（最短 2 字，实测 42 题中 2 字 13 条、3 字 12 条、≥4 字 17 条），所以读数**不可与单字声调对照**。它衡量的是「这一段话整体在往上走还是往下走」，不是「这个字的第几声」。
2. **≥4 字的题主动放弃调型。** 17/42 条（整句 8 条、家词 8 条、新词 1 条）不出调型读数，只给时长、平均基频、F0 范围、动态半音、浊音帧占比——句子的调型由多个音节叠成，报一个数字没有意义。
3. **整句与双音节词的调型会被读成「不可辨」或「平」。** 这是上面那条的直接后果：切不出音节，就只能报整段走向。
4. **类别是自动估计。** 环境噪声、气声、低音都会让 F0 提取失败；界面上的**灰点**就是低置信帧，**「浊音帧 n / 总帧 m」**告诉你这一条录得有多干净。
5. **削波和脆响会吞掉轻声录音。** 一声脆响会把能量分位拉高，让后面的轻声被判为静音。所以界面必须显示浊音帧比例，光看「有没有曲线」会被骗。
6. **非专业录音。** 手机麦克风 + 房间混响，不能用于音系描写，只能用于家庭对比。
7. **样本小。** 一个人一个家庭，结论只能描述，不能推断（理由见上面的「分布观察」）。
8. **数据只在本机。** 清了浏览器数据就没了——所以**录完一定要导出**，导出的 HTML 才是真正的存档。
9. **听音选词测验只是演示。** 它测的是「你记不记得自己录过什么」，**不构成任何学习效果证据**，不要写进结论。

## 六、录制须知（第一次打开时也会弹一次）

1. 录音只存在这台电脑的浏览器里，**不上传任何服务器**。
2. 录长辈（尤其祖辈）之前，**先告知用途并取得同意**。
3. 被录的人随时可以要求删掉对应条目（列表里的「删」按钮，或「清空全部」）。
4. 导出的文件可能被转发出去，**转发前请自己判断**里面有没有不愿外传的内容。

## 七、如果还要往前走一步

现在这套只记录「说法」。再加一层「孩子跟读」就完整了：孩子听完录一条，两条 F0 曲线叠在同一张图上——**像不像，眼睛能判断**，不需要任何识别服务。

那时录入动作本身就是学习动作，也是传承动作：孩子录的那一条，就是下一个人的材料。
